# Стискання зображень карток місій

`scripts/optimize_mission_previews.py` використовує Pillow, який уже є в
`requirements.txt`. Скрипт працює без мережі та бази даних. Шлях до проєкту
визначається за розташуванням скрипта, тому поточна робоча папка не важлива.

Спочатку перегляньте очікувану економію без зміни файлів:

```bash
python scripts/optimize_mission_previews.py
```

Застосувати оптимізацію:

```bash
python scripts/optimize_mission_previews.py --apply
```

На Windows можна використати `.venv\Scripts\python.exe`, на сервері —
`venv/bin/python` замість `python`.

За замовчуванням скрипт бере актуальні `img` з `my-app/src/lib/missions.js`:
зокрема `cassini_probe.jpg`, `gaia_telescope.jpg` та інші файли, навіть якщо
вони не називаються `preview.jpg`. Відсутні локальні зображення пропускає
з позначкою `MISSING`. Старі `preview.jpg`, які не використовуються картками,
та зображення галерей не обробляє.

Довша сторона зменшується до 960 px зі збереженням пропорцій, без обрізання
і збільшення маленьких зображень. JPEG зберігається з якістю 82, оптимізацією
та progressive-кодуванням; PNG зберігає прозорість; WebP — свій формат.
EXIF-орієнтація застосовується перед видаленням метаданих. Керування кольором
зберігається. Файл замінюється лише якщо результат менший за поточний.
Назви та URL залишаються незмінними.

Додаткові параметри:

```bash
# Окремі місії, спочатку лише звіт
python scripts/optimize_mission_previews.py --mission cassini gaia

# Інші розміри та якість
python scripts/optimize_mission_previews.py --max-size 800 --quality 80 --apply

# Також наявні зображення, завантажені через адмінку в data/missions/
python scripts/optimize_mission_previews.py --include-uploads --apply
```

Перед заміною оригінал копіюється в
`data/mission-preview-optimization/originals/`. Поруч лежить `manifest.json`
із контрольними сумами й параметрами: повторний запуск пропускає вже
оптимізовані файли, а зміна параметрів обробляє збережений оригінал.
Новий завантажений файл із іншою контрольною сумою обробляється знову.
Ця папка виключена з Git правилом `/data/`; збережіть її для відновлення
оригіналів. Скрипт не перезаписує готову React-збірку.

Після застосування до `my-app/public/` потрібно заново виконати
`npm run build` у `my-app/` і розгорнути збірку. Для файлів `data/missions/`
перезбірка не потрібна. Оскільки URL не змінюються, раніше завантажені копії
можуть залишитися в кеші браузера або CDN до оновлення чи очищення кешу.
