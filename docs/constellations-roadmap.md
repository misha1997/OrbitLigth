# Розвиток «Сузір’їв» і SEO

Аудит вихідного коду від 28.10.2026. Пошукові частоти, реальна індексація та
показники Search Console не перевірялися; пріоритети нижче — рекомендації на
основі реалізації сторінки.

## Що є зараз

- Інтерактивна карта містить 88 сузір’їв, але стартовий опис говорив лише про
  вісім популярних. Опис уточнено українською й англійською.
- Сервер уже формує title, description, canonical, hreflang, Open Graph,
  WebPage і BreadcrumbList. Маршрут є в загальному sitemap.
- На сторінці бракувало `useSeo()`: після SPA-переходу могли залишатися метатеги
  попереднього маршруту, включно з `noindex` від відфільтрованих новин.
  Підключено оновлення метаданих і відповідної структурованої розмітки.
- Title й description уточнено для обох мов. Сервер використовує ті самі
  словники, що й клієнт.
- Основний зміст сторінки — карта. Інформація з вибраних об’єктів не замінює
  відкритого довідкового матеріалу з постійними посиланнями.
- Детальні описи є для 18 сузір’їв; інші отримують загальні заглушки.
- У коді є необов’язковий prerender для ботів, вимкнений за замовчуванням.
  Фактичні налаштування production не перевірялися. Для нових довідкових
  матеріалів краще віддавати однаковий зміст у початковому HTML усім відвідувачам.

## Рекомендований порядок

Виконано перший пункт погодженого в чаті списку: додано 8 двомовних
сторінок сузір’їв, каталог посилань на головній сторінці, схеми та переходи
до відповідної ділянки інтерактивної карти. Для нових сторінок працюють
початковий HTML, окремі метадані, мовні alternates, sitemap і справжні 404.

### Оновлення матеріалів

- Джерело текстів: `my-app/src/data/constellationGuides.json`.
- Компіляція HTML, схем, каталогу та CSS: `node scripts/build-constellation-guides.cjs`.
  Це також виконується автоматично перед `npm run build` у `my-app`.
- PNG для соціальних прев’ю зберігаються в Git. Для їх оновлення запустити
  той самий скрипт з `--images`; потрібен пакет `sharp`, доступний через
  звичайний Node resolution або шлях у `CONSTELLATION_SHARP_MODULE`.
- Згенеровані JSON/SVG/CSS не редагувати вручну. Сервер і React використовують
  однаковий HTML, сформований скриптом.

## Шаблон сторінки сузір’я

Приклади реалізованих адрес: `/ua/suzirya/orion` і `/en/constellations/orion`.

- Українська, англійська й латинська назви; скорочення IAU.
- Коротка схема з підписами та кнопка «Знайти на інтерактивній карті».
- Як знайти: орієнтири, сусідні сузір’я, найкращий сезон; залежність від широти.
- Найяскравіші зорі та цікаві об’єкти з поясненням видимості неозброєним оком,
  у бінокль чи телескоп.
- Історія й міфологія з відокремленням їх від астрономічних фактів.
- Джерела, автор/редактор і справжня дата перевірки матеріалу.
- Контекстні посилання на інші сузір’я, темне небо, метеори й галактики.

## Технічні вимоги

- Один набір перевірених даних для HTML, клієнта й метаданих. Не створювати
  десятки сторінок лише із загальними заглушками.
- Основний текст, зображення та звичайні посилання доступні без натискання
  на canvas. Серверний/статичний HTML має збігатися зі змістом після запуску JS.
- Для нових адрес: окремі title/description, self-canonical, мовні alternates,
  sitemap, breadcrumbs, справжній 404 для невідомих сузір’їв.
- Параметри камери, масштабу та місця спостереження не створюють окремих
  індексованих копій одного матеріалу. Не публікувати точні координати
  користувача в canonical, sitemap чи посиланнях для поширення.
- Схеми сузір’їв — легкі SVG або зображення з розмірами та змістовним alt.
  Для сторінки — окреме Open Graph-прев’ю із зоряною картою.
- Реальні параметри з HYG/SIMBAD/Gaia та знімки DSS2/CDS завантажувати для
  відкритої картки, кешувати й показувати джерело. Не підмінювати відсутні
  значення випадковими чи загальними значеннями на кшталт «весна».
- Не створювати автоматично сторінку для кожної зі 112 тисяч зір. Почати
  з добре описаних яскравих зір, якщо довідник сузір’їв уже наповнений.

## Перевірка результату

- Перевірити початковий HTML і DOM після переходу з іншої сторінки для обох мов.
- Перевірити в Search Console фактичну індексацію та запити; не обіцяти позицій
  або зростання трафіку без вимірювання.
- Стежити за швидкістю початкового завантаження та реакцією карти на телефоні.
- Вимірювати відкриття карти, перехід до довідника та завершення навчальних вправ.
